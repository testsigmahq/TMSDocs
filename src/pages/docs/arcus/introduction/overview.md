**Arcus keeps your test cases, test plans, and test runs in one place, and uses AI to generate, automate, and track them for you.**

---

Arcus by Testsigma is a quality intelligence test management platform for QA teams. It gives you a structured home for test cases, test plans, test runs, and reports, so your team is not maintaining spreadsheets or switching between disconnected tools.

AI works on top of that foundation. In QI Home, Arcus generates test cases from your requirements, tracks coverage against your modules, builds test plans, automates execution, and captures developer activity from GitHub and CLI coding tools so your coverage stays current with what your team is building.

You can use Arcus fully manually, fully through AI, or anywhere in between. Everything the AI generates lands in the same library your team manages by hand.

---

## **How Arcus Is Organized**

Arcus has two layers.

**Core test management** is where you create and organize projects, test cases, test plans, and test runs, and where results and reports live. This layer works the same whether test cases are written manually or generated by AI.

**QI Home** is the AI workspace. You provide context, such as user stories, PRDs, designs, documents, or developer activity, and Arcus generates test cases mapped to your modules. You review and accept the cases, and coverage, test plans, and Quality Intelligence Metrics update as you go.

---

## **QI Home**

[QI Home](https://testsigma.com/docs/arcus/qi-home/overview/) is where Arcus generates test cases, tracks coverage, and automates execution using AI.

There are two ways to start test generation. In **Ad-Hoc**, you attach context sources yourself, such as Jira, Azure DevOps, Linear, or ClickUp stories, Confluence pages, Figma designs, files, or video recordings, and trigger generation on demand. In **Sprints**, Arcus detects a sprint start in your connected project management tool and begins generation from the linked stories automatically.

After generation, you review and accept test cases, and QI Home tracks the results. Coverage and Gaps shows how much of each module is covered. Test plans are generated automatically in four types: Smoke, Feature, Regression, and Deep Regression. Five Quality Intelligence Metrics in the session header, Coverage, Pass Rate, Confidence, Release Readiness, and Release Gate, tell you how confident you can be in the current build. See [Quality Intelligence Metrics](https://testsigma.com/docs/arcus/qi-home/quality-intelligence-metrics/) for how each metric is calculated.

**Automation** turns accepted test cases into automated ones without scripts. Agentic Learning walks through a test case on your live application, in the cloud or on your local device, and generates automated steps. Copilot executes those steps in a browser with live controls to pause, edit, and save as it runs.

**Developer Context Mapping** connects the tools your developers already use to test generation. When developers work in Claude Code, Cursor, GitHub Copilot, or Codex, or open pull requests in GitHub, Arcus captures that context and surfaces it in the **Unmapped Context** view. You review the AI-generated suggestion for where each entry belongs and map it, and Arcus generates or updates test cases from the captured changes. See [Overview: Developer Context Mapping](https://testsigma.com/docs/arcus/qi-home/context-mapping/overview/) for how the mapping model works.

## **Core Test Management**

- [Projects](https://testsigma.com/docs/arcus/projects/manage-projects/) organize your testing work; each project holds its own test cases, plans, runs, and settings.

- [Test Cases](https://testsigma.com/docs/arcus/test-cases/manage-test-cases/) are the building blocks of your library, with steps, expected results, custom fields, and version history.

- [Step Groups](https://testsigma.com/docs/arcus/step-groups/create-step-groups/) let you reuse a common sequence of steps across multiple test cases.

- [Data Sets](https://testsigma.com/docs/arcus/data-sets/manage-data-sets/) hold the input values your test cases run against.

- [Test Plans](https://testsigma.com/docs/arcus/test-plans/manage-test-plans/) group test cases into a scope you intend to run, such as a release or a regression cycle.

- [Test Runs](https://testsigma.com/docs/arcus/test-runs/create-test-runs/) record execution: who ran what, the result of each case, and any defects logged.

- [Test Capture](https://testsigma.com/docs/arcus/test-capture/overview/) is a browser extension that records your actions, logs, and screenshots while you test, and turns them into test cases or bug reports.

- [Reports](https://testsigma.com/docs/arcus/reports/view-reports/) show execution results, requirement traceability, and dashboards across your project.

## **Integrations**

- [Integrations](https://testsigma.com/docs/arcus/integrations/jira/) connect Arcus to Jira, Azure DevOps, Linear, ClickUp, Confluence, and Figma for requirements, defect tracking, and context sources. Jira and Azure DevOps also support two-way sync, so test cases and runs can be managed from either side.

- [Imports and Exports](https://testsigma.com/docs/arcus/imports-and-exports/csv-file/) bring your existing test cases in from TestRail, Zephyr, BrowserStack, or CSV files, and export your library out.

- [CI/CD Integrations](https://testsigma.com/docs/arcus/ci-cd-integrations/jenkins/) connect Arcus to Jenkins, GitHub Actions, GitLab, Azure DevOps, CircleCI, and Travis CI.

- [API Reference](https://testsigma.com/docs/arcus/api-reference/overview/) lets you read and manage Arcus data programmatically.
